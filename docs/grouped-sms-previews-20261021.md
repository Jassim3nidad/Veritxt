# Grouped SMS reports with sender and preview

At the user's explicit request, each incoming Veritxt report now identifies its numeric SMS sender and displays a short plain-text message preview while unlocked. Example: **5550804 · High Risk**, followed by the start of that message and the existing score-driven gauge. Expanding a child shows the preview, numerical risk index, model category and initial analysis. View report opens that exact pending message through the existing analysis flow. Dismiss removes only that message's report.

Reports share a native notification group. When at least two are active, a quiet count-only header reads **5 SMS reports**, for example. Expanding the group reveals one child per received SMS. The header is a navigation/display item, not another message or analysis result. Its count is refreshed from Android's actual active children after publishing, opening and dismissal; once created, it updates to **1 SMS report** when only one remains, then disappears after the last report is removed. This preserves the final child because Android may cancel remaining children when a group header is cancelled. Swiping the entire group dismisses its children and pending handoffs. The summary has no link to an arbitrary message. Individual reports retain their separate opaque tags and PendingIntent identities. The native Android Messages app still controls its own notifications; Veritxt does not silence them.

Preview text is limited to 90 Unicode code points plus an ellipsis when truncated. Control characters, bidi formatting and line breaks are replaced with spaces. Text is plain, with no link spans, and the preview builder does not read or verify sender identities or fetch URLs. The numeric sender comes only from the SMS metadata; an unsupported or inconsistent originating address becomes **Unknown sender**. No sender is inferred from message text.

Child reports use secret lockscreen visibility for all risk levels, so their sender, preview, score and gauge stay off the lock screen. Only the count-only group header can appear there. No raw message or sender enters the View report/Dismiss PendingIntent extras or data URI; these still use opaque IDs. Message content and sender remain outside app storage. Unlike earlier versions, bounded previews and sender labels now enter Android notification extras by design: Android notification history and apps with notification access may retain them. Hiding a report on the lock screen does not remove notification history.

Privacy notice version increases to 2 and incoming-SMS consent copy now explains previews and system notification history in English, Filipino and Tagalog. Existing installations must accept the updated notice through the normal app flow before automatic notifications resume. Clearing local preferences clears the current grouped reports and pending messages. No new permission, model retraining, risk-weight or threshold change is included.

Build with `scripts/build_old_binary_svm.ps1`. Verify using `python scripts/verify_all_sms_notifications.py --initial-reports --one-to-one --linked-cashback --output <fresh-directory>`. Added Android checks cover bounded text with emoji/control characters, generic grouping/counts, secret child visibility, and independent child versus group dismissal. Real-modem checks verify sender/preview labels, exact message actions, all risk levels, and five identical SMS producing five child reports under a five-report header.
