## Actual model-content and mathematical checks

All 5,000 vocabulary features were examined with the prior blocker patterns: **zero** terms with a run of five or more digits and **zero** masked-identifier terms. Additional scans found no literal email/URL strings, long mixed identifiers or very long tokens. This resolves the previously observed numeric/masked-feature blocker for this different artifact. It is not a claim that regex can prove absence of names or every possible identifier. No human vocabulary/redaction sign-off was fabricated.

Source model SHA-256: `d91f010a004e1fcfef6e4567389007cb81d16e1f6d0f258c263483b2b60d0d77`. Private converted model SHA-256: `ab7105a11cf62e7cd2b268ad84181ac61ab1ad6f7237973c518b2bd6fdae9e1b`. The asset contains only inference parameters/metadata, with reference messages and source guides excluded.

The contract is lowercase Python Unicode word tokens, consecutive unigrams/bigrams, raw term counts, supplied IDF and L2 normalization. Unknown tokens remain in sequence before bigram construction. Vocabulary order is preserved by the exported numeric indices, not resorted alphabetically. All indices/vector dimensions, finite scalars, positive IDF and class order `[ham, smishing]` pass validation. Training placeholder removal and vocabulary filtering are pre-fit steps; no runtime text rewriting was added.

The producer exports `coef_folded = a * coef` and `intercept_folded = a * intercept + b`, and the model explicitly marks this folding. Runtime therefore computes **sigmoid(coef_folded · normalized_tfidf + intercept_folded) once**. Schema v4 rejects separate runtime calibration fields. The source's a/b are not copied into executable runtime calibration. Applying them again would deviate by as much as 0.22006 on inspected probes. Original unfurled fitted objects were not supplied in the model archive; numerical identity to those absent objects cannot be independently certified.

The matching guide specifies **score > 0.50**. This candidate preserves that provisional strict boundary: equality is not suspicious. The model JSON itself contains no threshold. We did not choose an optimum from the already-exposed threshold table or inherit the prior candidate's >=0.40 rule. Empty/unassessable input remains “Unable to assess”, not a legitimate-message classification; oversized input fails gracefully.

Five rounded matching-guide references pass within 0.00005 (worst 0.00004705); pairing this model with the old guide is rejected. Seventy supplied full-precision scores match independent arithmetic, and 90 cases total cover guide references, supplied diagnostics and existing invented Unicode/long/unknown/empty probes. Python maximum discrepancy is 2.78e-16; JVM and Android are 3.33e-16, against a 1e-10 tolerance. Runtime policy produces 83 scored results and seven abstentions. Counts include repeated probes; they are not 90 independent evaluation samples.

## Research findings remain provisional

Recalculation of the supplied five grouped, with-additions, calibrated rows gives mean phishing F1 **0.940979**, precision **0.975458**, recall **0.908971**, and mean added-legitimate false-positive rate **0.002778**. The table sums to 49 caught added-scam predictions out of 49; repeated rounds mean this is not proof of 49 distinct independent scams. These reproduce CSV arithmetic, not dataset labels, model fitting or real-world performance.

The two supplied “fresh” diagnostic sets have already informed comparisons and scope selection. In particular, HANDOFF says the casino inclusion choice followed a drop on the 22 scam probes when casino messages were excluded. That exposes the tests to development decisions. They must remain documented as exposed, regardless of when they were first written. Their repeated use, tiny size and AI-assisted labels prevent a defensible claim of improvement from a one- or two-message difference. Aggregate LR4 rescoring is in the audit JSON; no predictions were hardcoded to preferred labels.

Other limitations:

- Primary and addition decisions are explicitly AI-assisted and await human confirmation; a nonempty proposed label is not an independent annotation. Real affiliation and financial-scope decisions remain unresolved, particularly branded casino advertising and borderline offers.
- Each supplied round holds out one grouped fold, but records can change roles across seeds. Across-seed SD and pooled reliability bins do not establish independent uncertainty or prospective calibration. Label-blind grouping helps but cosine similarity is not a reviewed semantic/template partition.
- The threshold options are computed on held-out test predictions. Selecting a threshold from that table is another development use of those tests. The retained 0.50 guide/default threshold is provisional, not independently optimized or validated.
- The final export is refitted on all claimed 2,738 rows. The reported per-round models are not this full-data artifact on an unseen cohort. Original model objects, complete training-history/exposure records and independently reserved confirmation data are still needed.
- Supplied government-fund and no-link OTP-request probes expose remaining coverage gaps. Successful fitting of Platt scaling does not establish a reliable real-world “chance of fraud”.

There is no new permission, label, adviser approval, unseen-test declaration, winner or public redistribution clearance in this integration. These research limitations remain visible and do not alone prevent the authorized private software experiment.
