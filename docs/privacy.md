# Privacy and SMS behavior

## Data lifecycle

Typing/pasting/shared text is held in ViewModel StateFlow only. No SavedStateHandle or Compose saveable state is used; the activity clears saved bundles. Share extras and ClipData references are removed from the Activity intent. A checking result retains only a class/score, sanitized domain, and hour source time; raw input is cleared immediately after inference. Navigation away from the session, Android back, backgrounding (`onStop`), or clear resets the session and cancels its coroutine. Rotation also clears the session intentionally. The app does not attempt to erase the user's system clipboard or the originating app's copy. JVM strings are garbage-collected; this is reference clearing, not a promise of forensic memory zeroization.

Screenshots, screen recording and screen sharing are allowed, as requested on 20 October 2026 for showcasing the app; `FLAG_SECURE` is no longer set. The Activity remains excluded from recents. Keyboard autocorrect is disabled and a password-class keyboard hint discourages keyboard learning; the operating system and user's chosen keyboard are outside the app's control. No backup, logs of messages/errors, analytics, network access, raw-text job inputs, or persistence of scan history exists. DataStore saves only privacy-notice acceptance, onboarding completion, incoming-SMS consent, and display/language settings. The earlier "Your city" setting was removed (an upgrade migration deletes the old value); reports no longer carry a location. Privacy notice version 2 explains preview display and system notification history. Clearing local preferences removes all of these, clears active preview reports and pending messages, and turns scanning off; Android's permissions are managed by Android.

The Android framework delivers shared/SMS text in system-owned intents. SmishGuard does not save those intents or request inbox-reading access. At the user's request, unlocked incoming-report notifications now contain a numeric sender label and a bounded plain-text preview, plus the existing score/category. Android notification history and notification-access apps may retain these previews. Child reports use secret lockscreen visibility; the public group header contains only a count. PendingIntent extras and data URIs remain opaque and contain no message text or sender. See [grouped preview behavior](grouped-sms-previews-20261021.md).

## Domain policy v1

Reporting extracts explicit HTTP(S) or `www.` candidates, parses using `java.net.URI`, requires a valid host, rejects credentials, malformed URI encoding, backslashes, IP literals, and unknown suffixes. It strips trailing DNS dots and normalizes ASCII case. Non-ASCII hosts that URI cannot safely parse are omitted; IDN/punycode registered labels are omitted conservatively.

Supported registry suffixes are deliberately finite: `com`, `org`, `net`, `edu`, `gov`, `io`, `ph`, `com.ph`, `org.ph`, `net.ph`, `gov.ph`, `edu.ph`, `co.uk`. The longest matching suffix is selected. Only one label immediately above the registry suffix is retained. **All subdomains are discarded**, including customer/account names and private hosting tenants. Example: `alice.github.io/token` becomes `github.io`, not `alice.github.io`; `customer.example.com.ph` becomes `example.com.ph`. Registered labels containing digits, punycode or more than 40 characters are omitted. Unknown suffixes are omitted rather than guessed. This is a conservative reporting policy, not a full public-suffix implementation or a link-legitimacy detector.

For multiple links, only the first successfully sanitized domain is offered. Unparseable links produce no domain. This loses detail deliberately; no parser can prove a registered domain itself never encodes a person's name, so the preview remains important and users can decline reporting. No domains are sent in this milestone. No link is opened, fetched, resolved, or tested against a remote reputation service.

Only a controlled brand choice is accepted; there is no free-text field that could accidentally contain private data. A future submit action must send the exact preview from `ReportPayload.json()`, whose factory requires a nonexperimental, nonsynthetic finite prediction. Metadata is not retained after the session.

## Incoming SMS

`SMS_RECEIVED` receiver requires sender-side `BROADCAST_SMS`, checks RECEIVE_SMS and telephony availability, obtains `goAsync()`, and processes the platform-provided PDU segments in order on Dispatchers.Default. Message bodies and a consistent numeric originating address are held temporarily for the optional manual blocking flow. Malformed/empty/oversized messages are ignored. A seven-second cooperative timeout bounds work, with input/model size caps. `finish()` always runs. No WorkManager job or persistent queue is created. Consent and permissions are checked before processing and again before notification publication.

With incoming SMS enabled, every valid received SMS gets an initial scan report. In builds whose detector permits automatic analysis, notifications show Low/Medium/High Risk, the provisional risk index and the model category when available. Expanded notifications add a short analysis and explain that the risk index is not a fraud probability. Unsupported automatic models, missing models, errors and the five-second cooperative inference deadline produce **Unable to assess SMS** without a numerical score. A busy inference permit is retried within that same deadline so nearby messages can each be assessed. **View report** opens and rechecks the exact pending message. Classifier parameters, risk weights and thresholds are unchanged. Notification extras now include the numeric sender and a preview bounded to 90 Unicode code points, as explicitly requested by the user. Control/bidi formatting is stripped and no clickable link spans are added. PendingIntents still contain no text or sender. Reports are grouped under one generic count-only header; each received SMS has an independent child report and matching actions.

Only RECEIVE_SMS and POST_NOTIFICATIONS are declared. There is no READ_SMS, SEND_SMS, contacts, location, identifier, or default-messaging-role request. Notifications use separate neutral-prompt and High Risk channels, runtime permission on API 33+, and app/channel enable checks. Incoming preview reports use secret lockscreen visibility at every risk level; only the count-only group header may appear on the lock screen. Legacy prompts without an initial report retain their generic public version. Blocking one channel does not disable the other. Notification denial suppresses posting independently. Permission denial or revocation leaves manual/shared checks available. Revocation does not cause automatic rerequests; the settings screen provides system settings access.

Installer allowlisting can prevent RECEIVE_SMS from being granted even for a sideloaded APK. Force-stop, device battery policies, missing telephony and protected SMS delivery rules limit coverage. The app does not monitor RCS or any other messaging app. Its notification is separate from the default SMS app's inbox notification.

## Supplied asset review

Only converted model parameters and technical metadata are bundled in the development APK. The dataset, original guide and parity probes are excluded. The supplied vocabulary has two identifier-like numeric terms flagged in the aggregate audit; their ownership/redaction status remains unresolved and needs team review before broader distribution. No raw message examples are printed in the audit. App storage marker checks establish only the tested paths; they are not forensic memory-erasure or packet-capture claims.

## Safe backend/evidence handoff

The private deployed model contains identifier-like numeric vocabulary terms inherited from training data. The model therefore remains excluded from the public repository. Future retraining should remove standalone numeric tokens of five or more digits and re-run parity and evaluation tests.

Known numeric vocabulary literals were omitted from repository-bound evidence; full reference SMS examples and the literal intercept were also omitted. Original ZIPs were unchanged; the private training ZIP was never accessed. Backend accepts metadata fixtures only, rejects unknown keys without echoing their names, stores no client IP column, suppresses development access logs and has no remote font resources. Demo rows are stored with a server-only flag and excluded from the normal report view. No real reports were submitted.

Android reporting remains disabled and INTERNET permission absent. No retention/authentication/deployment assurance follows from the prototype; every [reporting-readiness gate](reporting-readiness.md) remains pending. Metadata itself may be sensitive; access/error/proxy logs require future review. The staged checker now examines index bytes without opening private data/models; pattern checks supplement manual review and cannot prove arbitrary text contains no personal data.
