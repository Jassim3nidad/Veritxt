## Recovery guarantees

The app caches successful initialization only and serializes loading. Each manual inference holds an application-scoped permit until work actually returns. A new request receives a useful busy response instead of creating a queued/overlapping job. Session generation checks and cancellation prevent late publication after clear, navigation, background, another session or deadline. Slow guidance appears after seven seconds; at sixty seconds the UI stops waiting, clears input and shows failure/restart guidance.

These are UI/cancellation guarantees, not a hard native deadline. A synchronous ONNX call or file copy may continue after cancellation, retaining transient arguments until it returns. Nothing persists those arguments. A hung native call requires Android Force stop/reopen; retries cannot start another native job while it runs. Loading and inference run off the main thread. The one successful ONNX session is process-owned; tensors, result handles and session options close with use blocks. Failed session-interface validation closes its newly created session. Explicit session close is synchronized with raw inference and idempotent; a shared OrtEnvironment is not incorrectly closed per call. Normal Android process teardown releases the process-owned session.

ModelCache hashes any cached model before use. Corrupt/incomplete files are replaced from the original bundled bytes. A fixed pending file is copied, flushed with fsync, hash checked and atomically renamed in the same directory; stale pending files are discarded, and exceptions remove partial copies. The final file is reverified. Atomic publication prevents a partial model from becoming loadable; the next launch repairs loss or corruption after a process/power interruption. No absolute filesystem durability guarantee is claimed beyond recovery and verification.
